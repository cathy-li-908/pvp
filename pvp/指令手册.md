# pvp —— 【尽伏诛】PVP 指令手册

> 插件名 / namespace：**`pvp`**（OlivOS 插件列表里显示为 `pvp`）。游戏名「尽伏诛」可被骰主替换，下文出现的 `【尽伏诛】` 均指「当前游戏名」。
>
> 所有自定义指令统一以 **`【PVP】`** 开头（PRD 第 1 节）。
> 掷骰保持青果原生写法，直接发 **`.raN`**，不加任何前缀。
>
> 标记说明：
> - ✅ **PRD 原生** —— PRD 5.x 指令表里就有的指令
> - ➕ **扩展** —— PRD 里没写、但缺了会导致玩法走不通的补充指令（见 [README 的差异说明](./README.md#三相对-prd-的扩展与差异)）

## 二、玩家指令

玩家指令只能发在**自己的个人群**里，其他群发会被拒（防止冒名）。

### `【PVP】帮助`

（`help` / `说明` / `规则` 等价；只发 `【PVP】` 也当帮助）
输出玩法速查。

> 另可用青果原生 `【PVP】` 帮助文档：`.help PVP`

### `【PVP】血量`

> 来源：➕ 扩展。PRD 2.2 写了玩家可「查看本人血量」，但 5.3 的指令表里没有对应指令。

```
【张三】
血量：175 / 200
状态：正常
攻击值：60（每回合 .raN 的基础值，由骰主单独设定）
铜币：1000
今日主动次数：1 / 3
活动时段：开放中
```

- 「血量：175 / 200」里的 200 是**当前血量上限**（骰主用 `设置血量上限` 设的），不是写死的；
  它和「初始血量」（新玩家出生血量）是两个独立配置项，可以不同
- 「攻击值」就是每回合掷骰列表里 `.raN` 的基础值；没被骰主单独设过时括号里不会有「由骰主单独设定」

濒死 / 死皮时会在后面追加一行说明，例如：
`（濒死：无法主动发起 PVP，可被挑战，可使用场外药）`

### `【PVP】铜币`

只看铜币余额，输出一行。

### `【PVP】商城`

列出在售道具、当前售价与效果：

```
【商城】

—— 场外型 ——
大还丹　300 铜币　回复 100 血量
小还丹　150 铜币　回复 50 血量
解毒丸　120 铜币　解除中毒状态（预留，当前版本无中毒玩法）
幻息丹　200 铜币　效果待定（当前版本无实际效果）

—— 全场型 ——
遁隐符　800 铜币　整场取消，血量维持，背包不动，对局立即结束

—— 回合型 ——
胜临符　400 铜币　指定回合自身 .raN +10
错影符　400 铜币　指定回合对方 .raN -10

购买：发送「【PVP】购买 道具名」
查看背包：「【PVP】背包」
```

### `【PVP】购买 道具名 [数量]`

`[数量]` 是扩展参数，不填默认 1。

限制：

- 死皮状态不能购买
- 战斗中（对局进行中）不能购买
- 铜币不足会被拒，且不会出现负数余额

### `【PVP】背包`

按固定顺序（场外型 → 全场型 → 回合型）列出自己持有的道具及其效果：

```
【背包】张三
血量：175 / 200（正常）
铜币：1000

大还丹 ×2　回复 100 血量
胜临符 ×1　指定回合自身 .raN +10
```

背包为空时显示 `（背包是空的）`。

### `【PVP】使用道具 道具名 [回合数]`

这是一条**双语义**指令，靠「你在不在对局里」自动区分：

| 你在哪 | 可用的道具类型 | 写法 |
| --- | --- | --- |
| 不在对局中 | 场外型（大还丹 / 小还丹 / 解毒丸 / 幻息丹） | `【PVP】使用道具 大还丹` |
| 对局中·声明阶段 | 全场型（遁隐符） | `【PVP】使用道具 遁隐符` |
| 对局中·声明阶段 | 回合型（胜临符 / 错影符） | `【PVP】使用道具 胜临符 2` |

要点：

- **回合型必须写回合号**，不写会被拒；全场型**不能**写回合号
- 回合号范围是 `1 ~ 当前配置的回合数`
- 同**一个回合只能放一个道具**（双方合计，PRD 4.8.2）。对方已经占了第 3 回合，你就不能再用回合型道具压第 3 回合
- 同一种道具在一场里最多用「每种道具限用」次（默认 1）
- **声明时立即从背包扣除**（PRD 4.8.3），声明后不可撤回
- **声明限时**：默认 10 分钟内双方没声明完，对局自动取消，已声明的道具和发起人的主动次数都会退回（可用 `【PVP】设置声明超时` 调整，配 0 关闭）
- 满血吃大还丹会被拒，且**不消耗**道具
- 解毒丸 / 幻息丹当前版本没有实际效果，使用会被拒且**不消耗**（避免误发一次白扣一件）

### 发起后的回执

发起 PVP 成功后，机器人只回复一句：

```
已收到 PVP 请求，排队中。
```

- **如果当前没有对局在打**：你的对局会**立刻开始**，紧跟着这条回执，你会在同一个群里直接收到「对局已匹配」通知和道具声明引导（不用等跨群推送）——这也就意味着「排队」其实是一瞬间的，队列里不会留着你这条请求
- 如果此时**有一场对局正在打**，会追加一行「当前有一场对局正在进行，结束后会自动开始你的对局。」——这不是卡住了：当前那场打完，你的对局会自动开始，两个群都会收到匹配通知和道具声明引导

### `【PVP】不使用`

表示「本回合我不声明道具了 / 声明完毕」。

- 双方都发完 → 立即进入掷骰阶段，**最后声明完的那个人当场收到掷骰列表**（另一个人由机器人直接把那份发到他的群）
- 重复发送是幂等的，会提示「你已经完成声明了」

### `【PVP】排队`

查看当前对局与排队情况：谁在打谁、你是排队中的第几位；对局处于掷骰阶段时还会显示**双方的掷骰进度**（发起方 X/N，被发起方 Y/N）——如果对局一直不结算，先用这条看看是不是有人少掷了。

### 掷骰阶段的回执

逐条发送掷骰列表里的 `.raN`，一条掷骰只回一条记录：

```
第 3 回合已记录：45（成功）
```

（掷骰前不再额外发「现在是第 N 回合，请发 .raX」的引导，与记录回执合并成一条；要查每回合该掷多少，看开局时收到的掷骰列表）

- 双方都掷满才会结算。你先掷满时会收到「你的 10 回合已全部掷完，等待对方掷骰。」——这时对方没掷满，**催对方补掷**，不要继续掷（多掷的不计分）
- 双方都掷满 → 「10 回合已全部掷完，等待结算。」，随后双方都会收到战报（掷出最后一骰的人当场收到，另一人由机器人直接把战报发到他的群）
- 如果某条掷骰收到「未被记录 / 与要求不符」的提示，说明这一掷**没有计入**，按提示重掷即可；不补上的话对局会一直等不到结算
- **掷骰限时**（➕ 扩展）：默认 30 分钟内双方没掷满，按已记录的结果直接结算，未掷回合按 0 伤害计并在战报中注明（可用 `【PVP】设置掷骰超时` 调整，配 0 关闭）

### `【PVP】战报`

重看**最近一场**与你相关的战报。

> 被发起人一侧的战报里，发起人显示为「神秘对手」（PRD 4.3.3 / 验收标准 13）。
>
> 战报只列**双方累计造成伤害**与胜负，**不展示双方的剩余血量**——血量是个人状态数据，
> 要查自己的血量用 `【PVP】血量`。

## 三、骰主指令

骰主 = OlivaDiceCore 的骰主名单成员（PRD 2.1）。用青果的 `.master` 系列指令管理即可，本插件不另存一份名单。

### `【PVP】注册后台群 游戏名`

```
【PVP】注册后台群 尽伏诛
```

- 声明当前活动的游戏名，之后所有消息模板里的 `【尽伏诛】` 会自动使用这个名字
- 同时把**发出这条指令的群**登记为后台群
- 未注册时，除本指令外的所有指令都会被拒绝

### `【PVP】添加管理 QQ号` / `【PVP】移除管理 QQ号`

```
【PVP】添加管理 987654321
```

### `【PVP】结束活动 [确认]`

两步确认：

1. `【PVP】结束活动` → 只弹出确认提示，**不删任何东西**
2. `【PVP】结束活动 确认` → 删除所有玩家、背包、铜币、队列、对局、战报与活动配置

> 活动周期走完后也要用这条指令清理，否则下次开活动会带着旧数据。

## 四、后台管理员指令

绝大多数管理指令**在后台群和个人群里都能发**（PRD 4.1.3 / 5.2）。

### 管理指令一览

```
【PVP】管理
```

骰主与后台管理员都可用（➕ 扩展）。回一张按权限分组的清单，忘了有哪些指令时直接发这一条：

```
【PVP】管理指令一览（当前游戏：尽伏诛）

== 骰主专用 ==
【PVP】注册后台群　游戏名　在目标群注册后台群并声明游戏名
【PVP】添加管理　QQ号　把该 QQ 加进后台管理员名单
…（略）

== 骰主与后台管理员都能用 ==
【PVP】管理　本清单，随时回来查
【PVP】注册玩家　群号 QQ号 玩家名　…
【PVP】设置回合数　10　每场每人要掷几回合
…（略）

★ 玩家指令请看：【PVP】帮助
```

清单只分「骰主专用」与「骰主与后台管理员都能用」两组 —— 本插件里**骰主拥有后台管理员的全部权限**
（见第一节的权限矩阵说明），不存在「只有管理员能做」的指令。

清单里的**指令列表是从代码的路由表现场生成的**，不是手写文档，所以：

- 新增一条指令，清单里**一定**会出现它（漏写用法说明会被测试拦下，不会静默为空）
- 删掉指令，清单里也不会留下已经不存在的条目

### 注册玩家

两种写法：

```
【PVP】注册玩家 群号 QQ号 玩家名     ← 在后台群用
【PVP】注册玩家 QQ号 玩家名          ← 在那个人的个人群里用
```

例：

```
【PVP】注册玩家 123456789 987654321 张三
【PVP】注册玩家 987654321 张三
```

限制：

- 玩家名**全局唯一**
- 一个群只能绑定一个玩家
- 注册时按当前「初始血量」「初始铜币」「初始攻击」发初始资源（注册回执里会列出来）；
  出生血量不会超过「血量上限」，被上限压住时回执里会一并写出上限

### 活动参数

```
【PVP】设置活动日期 活动周期：2026-09-01 ~ 2026-09-02 每日开放：14:00 ~ 18:00
```

- 「活动周期」是活动从哪天到哪天，「每日开放」是每天几点到几点
- 日期支持 `2026-09-01` 或 `20260901`；时间必须带冒号，写成 `14:00`（全角冒号 `14：00` 也认）
- 写法很松：波浪线前后的空格写不写都行（`2026-09-01~2026-09-02` 也认），
  两段的标签可以省略（直接写 4 个值），「每日开放」写在前面也行，中文「至 / 到」当波浪线也认
- 设置成功后回执里会再带一次该格式示例

```
【PVP】设置初始血量 200
【PVP】设置血量上限 500
【PVP】设置初始铜币 1000
【PVP】设置初始攻击 50
【PVP】设置个人攻击 张三 60
【PVP】设置主动次数 3
【PVP】设置回合数 10
【PVP】设置每种道具限用 1
【PVP】设置声明超时 10
【PVP】设置掷骰超时 30
【PVP】设置伤害表 大成功=20 极难成功=15 困难成功=10 成功=5 失败=0 大失败=0
```

说明：

- **「初始血量」和「血量上限」是两个各自独立的数值**（都是 ➕ 扩展，1 ~ 100000），
  出厂默认都是 200：
  - `【PVP】设置初始血量 N`：**只管新玩家注册时的出生血量**，不动任何已有玩家
  - `【PVP】设置血量上限 N`：**血条能有多长** —— 道具回血的封顶值、血量显示的
    「当前 / 上限」里的分母、血量夹取的上界
  - 常见设法是**上限高、初始低**（例：上限 500 / 初始 200），新号从 200 血起步，
    靠回血道具与奖励把血线往 500 上养；反过来把初始设得比上限还大时，
    出生血量会被上限压住，回执里会明确警告并告诉你该把上限调到哪里
  - **上限调小之后**，血量高于新上限的老玩家会被削到上限；回执里会点名列出这些人，
    想补就用 `【PVP】修改血量` 单独补（但补不过上限）
  - 上限 ≤ 20（濒死线）时回执会警告：全场血量高于它的玩家都会被打成濒死
  - 初始血量 ≤ 20（濒死线）时回执会警告：新玩家一注册就是濒死状态
- **「设置初始攻击 N」是全体统一值**，而 **「设置个人攻击 玩家名 N」只覆盖某一个人**：
  - 个人值优先，没被单独设定过的人用统一值；个人值 1 ~ 100
  - 写 `设置个人攻击 玩家名 0` = **清除**个人设定，回落到统一值
  - 顺带一提：`【PVP】设置初始攻击 玩家名 60` 也是给个人设（不用记第二条指令）
  - 这两个数决定每回合 `.raN` 的基础值，改完**下一场**对局生效
- **「设置初始铜币」只影响之后注册的玩家**，不会重置已有玩家的钱包（避免误操作把全场经济清零）
- **「设置伤害表」支持增量更新**：只写想改的档位，没提到的保持原值
  ```
  【PVP】设置伤害表 困难成功=12
  ```
- 回合数上限 100（防止 `99999` 把机器人拖死）
- **「设置声明超时 N」**（➕ 扩展）：道具声明阶段超过 N 分钟没人声明完，
  对局自动取消——不结算、血量背包维持、已声明道具与发起人的主动次数退回，
  队列里排着的请求立刻顶上。**取消时双方都会收到一条通知**，写明是因为超时未完成道具声明：
  ```
  【尽伏诛】PVP 已结束
  因为超时未完成道具声明（超过 10 分钟），本场对局已取消。
  不结算伤害，血量与背包维持。
  ```
  `0` 表示不限制（恢复 PRD 原行为，卡住时用 `【PVP】强制结束` 兜底）。
  默认 10 分钟。没有这个超时的话，一对玩家都放着不声明，全场 PVP 都得干等——
  这正是「排队中之后再无下文」的根源。
- **「设置掷骰超时 N」**（➕ 扩展）：掷骰阶段超过 N 分钟没掷满，**按已记录的结果直接结算**
  ——已经打了一部分，取消会丢账，所以是结算而不是取消；未掷的回合按 0 伤害计，
  战报里会注明谁缺了几回合。`0` 表示不限制。默认 30 分钟。

### 资源与血量

```
【PVP】发放铜币 张三 500
【PVP】扣除铜币 张三 200
【PVP】修改血量 张三 150      ← 设为指定值
【PVP】修改血量 张三 +50      ← 增加（上限 = 当前血量上限，不是初始血量）
【PVP】修改血量 张三 -30      ← 减少（最低 0）
```

- **没有单独的「复活」指令**（PRD 2.1 明确）。把死皮的人改回 100 血，他就自然恢复正常了——状态是从血量现算的，不存在「血满了但还是死皮」的情况
- 改血量时提示会同时显示改前改后的状态：
  `血量：170（正常）→ 10（濒死）`

### 扩展管理指令

```
【PVP】设置道具价格 大还丹 500      ← 改价立即生效，不影响已售出的道具
【PVP】发放道具 张三 大还丹 2
【PVP】回收道具 张三 大还丹 1
【PVP】删除玩家 张三                ← 同时清掉他的队列请求与进行中的对局
【PVP】强制结束                     ← 立即终止当前对局：不结算、血量维持、道具返还
【PVP】配置                         ← 查看当前全部活动配置
【PVP】名单                         ← 查看全量玩家数据
```

## 五、发起 PVP 与掷骰

### 发起

在**自己的个人群**里发三行（同一行写也行，字段顺序即前后顺序）：

```
【尽伏诛】PVP
发起人：张三
被发起人：李四
```

- 第一行的游戏名必须是骰主声明的那个名字，写错了会提示当前正确的名字
- 发起后进入队列，同一时间只进行一场 PVP
- 校验顺序：已注册 → 状态正常 → 当日主动次数 → 活动时段 → 自己不在对局/队列 → 被发起人已注册 → 被发起人不是死皮 → 被发起人不在对局中
- **濒死（血量 1~20）不能主动发起，但可以被挑战**

### 匿名规则（PRD 4.3.3）

被发起人**全程不知道发起人是谁**：

| 位置 | 发起人看到的 | 被发起人看到的 |
| --- | --- | --- |
| 匹配通知 | `发起人：张三` | `发起人：神秘对手` |
| 战报 | `张三 累计造成伤害：30` | `神秘对手 累计造成伤害：30` |
| 死亡掉落播报 | `李四倒下了，其全部背包与铜币归 张三：…` | `李四倒下了，其全部背包与铜币归 神秘对手：…` |

### 掷骰

进入掷骰阶段后，机器人会给每个人一份**逐回合**的列表：

```
【本场共 3 回合，你的每回合掷骰值如下】

第 1 回合：.ra50
第 2 回合：.ra60      ← 你用了胜临符
第 3 回合：.ra40      ← 对方用了错影符

请逐条发送，一个回合发一条。
```

**必须按列表逐条发**。要点：

- 一个回合发一条，顺序不要乱
- 技能值和列表不符 → 该次掷骰**不计分**，并提示你重发正确的 `.raN`
- 不要用连掷 `.ra50#3`、不要用奖励骰/惩罚骰 —— 这些写法读不到结果，会提示「这一掷没被记录」
- 双方都掷满后统一结算，两个群同时收到战报

### 血量与状态（PRD 3.1 / 4.7.1）

| 血量 | 状态 | 能做什么 |
| --- | --- | --- |
| > 20 | 正常 | 可发起、可被挑战 |
| 1 ~ 20 | 濒死 | **不能主动发起**，可被挑战、可吃场外药 |
| = 0 | 死皮 | 不能进行任何玩法（不能发起、不能被挑战、不能买、不能用药） |

一方倒下 → 其全部背包与铜币归胜利方；**双方同时倒下 → 都不转移**。
